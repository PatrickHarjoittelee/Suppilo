Kuva pienennetään automaattisesti 96 × 96 pikseliin.
Microsoft ei tarjoa rajapintaa jolla Outlookin allekirjoituksen voisi hakea automaattisesti CRM:ään — liitä se tähän kertaalleen käsin: avaa Outlookin asetuksista oma allekirjoituksesi, kopioi koko sisältö (Ctrl+A → Ctrl+C) ja liitä yllä olevaan kenttään (Ctrl+V). Lisätään automaattisesti jokaisen Suppilosta lähetetyn sähköpostin loppuun. Jos logo tai kuva ei tule mukaan liittäessä — Outlookin kuvat ovat usein linkkejä jotka toimivat vain omassa Outlook-istunnossasi eivätkä siksi kopioidu luotettavasti mihinkään toiseen sovellukseen — tallenna kuva ensin tiedostoksi (esim. paina hiiren oikeaa näppäintä kuvan päällä → Tallenna kuva nimellä) ja lisää se sitten yllä olevasta 🖼️ Kuva -painikkeesta, tai liitä suoraan leikepöydältä (Ctrl+V) jos kuva on kopioitu kuvana (esim. kuvakaappaus).

Outlook-sähköposti
Käyttöönotto (kerran per organisaatio)
  1. Avaa Microsoft Entra ja luo uusi sovellusrekisteröinti (alustaksi Single-page application, tilityyppi vain tämä organisaatio).
  2. Liitä alla näkyvä Redirect URI sovellukseen täsmälleen sellaisenaan.
  3. Lisää API-oikeudet: Microsoft Graph → Delegated → Mail.Send + Mail.Read + Mail.ReadWrite, ja myönnä admin-suostumus koko organisaatiolle.
  4. Kopioi sovelluksen Application (client) ID Overview-sivulta ja tarkista organisaation verkkotunnus alla oleviin kenttiin.
🔗 Avaa Microsoft Entra – Sovellusrekisteröinnit
Täytetty valmiiksi oletuksena. Muuta vain jos kirjautuminen antaa virheen AADSTS50194 tai AADSTS90002 — silloin tähän tarvitaan sovelluksen todellinen tenant-tunnus (Entra → sovellusrekisteröinti → Overview → "Directory (tenant) ID").
Ei yhdistetty
Suppilo pyytää lähetysoikeuden (Mail.Send), lukuoikeuden (Mail.Read) ja luonnosten luontioikeuden (Mail.ReadWrite — tarvitaan, jotta viestin conversationId saadaan talteen ennen lähetystä ja vastaukset voidaan linkittää oikeaan tikettiin). Microsoft myöntää Mail.Read/ ReadWrite-oikeuden koko postilaatikkoosi, mutta Suppilon koodi käyttää niitä ainoastaan CRM:ssä tunnistettujen yhteyshenkilöiden kanssa käytyihin viesteihin — ei muuta postia selaa, muokkaa tai tallenna. Client ID ei ole salasana. Salasanaasi ei koskaan syötetä Suppiloon — kirjautuminen tapahtuu Microsoftin omassa ikkunassa. Jos tili on jo yhdistetty aiemmin: seuraava lähetys pyytää automaattisesti uuden hyväksynnän laajennetulle oikeudelle.

AI-personointi
"✨ Personoi avaus" -painike sähköpostin kirjoitusikkunassa ja tekoälyn ehdottamat uudet prospektit käyttävät valitsemaasi tekoälyä muotoilemaan tilin Signaali/Perustelu-tiedoista lyhyen, henkilökohtaisen avausrivin — tai etsimään uusia yrityksiä verkosta. Avain tallennetaan vain tähän selaimeen ja lähetetään suoraan valitun palveluntarjoajan omalle rajapinnalle — ei jaettua taustapalvelinta, ei kenenkään muun nähtävissä. Avain on oikea salaisuus, ei julkinen tunniste: jos se vuotaa, vain sinä voit kumota sen palveluntarjoajan konsolissa, CRM ei voi tehdä sitä puolestasi. Tekoäly voi tarvittaessa myös hakea täydentävää tietoa verkosta signaalin tueksi — palveluntarjoaja laskuttaa hauista pienen lisän normaalin tokenkäytön päälle omalta avaimeltasi.
